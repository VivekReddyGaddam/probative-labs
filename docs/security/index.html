Security and privacy

Built to need as little of your data as possible.

Probative Labs reads operational data such as tickets, cases and alerts. So it reads only what the analysis needs, runs where your data lives when required, and never judges individuals.

Data minimization

  • Read-only, least privilege. Connectors use a service account limited to the fields Probative Labs needs. Probative Labs never writes back to your systems.
  • Metadata first. Timestamps, categories, teams and outcomes. Free text is read only to type work, then dropped.
  • Pseudonymization at ingest. Names and user IDs are replaced with keyed hashes before anything is stored, using a separate key per customer. Raw uploads are not kept.
  • Team-level results only. Every result respects a configurable minimum group size. No screen shows an individual's productivity.

Employee relations and regulation

  • Works councils. Probative Labs provides a standard description of its team-level design for consultations, for example under Section 87(1) no. 6 of Germany's Works Constitution Act.
  • GDPR. Data processing agreement, an EU-region hosting option, and configurable retention with automatic deletion.
  • EU AI Act. Probative Labs evaluates AI programs, not people. It does not recruit, score, rank or monitor individual workers.
  • AI inside Probative Labs. Any AI used inside Probative Labs runs on model endpoints you approve. Your data is never used to train models.

Security program

  • TLS in transit and encrypted volumes at rest in hosted deployments; connector and single sign-on secrets encrypted in the database
  • Single sign-on (OpenID Connect), role-based access and a complete audit log
  • Strict browser security headers; no third-party scripts, trackers or analytics in the product
  • Independent penetration testing before general availability
  • Planned certifications, in order: SOC 2 Type II, ISO/IEC 27001, ISO/IEC 42001

To report a vulnerability, use the private reporting channel on our GitHub repository.
