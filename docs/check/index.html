Free check · runs in your browser

Did your virtual agent's "resolved" conversations hold?

Drop two ServiceNow exports. In about a minute you'll see how many conversations counted as resolved came back as a ticket within a week, next to your agents' own resolutions. Nothing is uploaded.

Nothing leaves your machine. This page's security policy (connect-src 'none') blocks every network connection, so it cannot send your data anywhere. To see for yourself, open your browser's developer tools on the Network tab before you run the check: no requests appear. The code is open: read it.

1. Virtual Agent conversations

In ServiceNow, open interaction.list, filter to Virtual agent = true for the months you want, and export as CSV with: Number, Opened for, Opened, State, State reason, Agent chat, Type.

2. Incidents for the same months, plus a week

Export incident.list as CSV with: Number, Caller, Opened, Resolved, and Category for the fix list. Use the same kind of person field as the conversations: both names, or both Sys IDs.

To keep names out of the exports, use the person's Sys ID instead of the name: in the list layout, expand Opened for (or Caller) and choose Sys ID. Do the same in both files so the people match.

Questions

Is this the full audit?

It uses the same definitions as the open engine's resolution audit and gives the same headline figures on the same files. The full audit also matches the type of issue, runs sensitivity checks and widens the range with a month-by-month check. Run it with pip install probative-labs, or book a call and I'll run it with you.

What counts as "came back"?

The same person opened an incident within the window after the conversation started. Some people come back after any help, so the same check runs on incidents your agents resolved in the same months, and only the excess counts as "did not hold".

Can I share the result?

Download the summary: rates and counts only, with no names, IDs or ticket contents. Send that, not the exports, if you'd like a second opinion.

Our virtual agent isn't ServiceNow.

Any export with a person, a start time and an outcome works: pick the columns after you drop the file, and set the outcome values that mean resolved under Options.
